# Settings

Every setting of the `edge` image is one environment variable with a secure default; an empty variable counts as
unset. At start the container checks every value. A value that is not allowed stops it, with a message naming the
variable and the allowed values. A value that is weaker than the default prints one line starting with `SECURITY:`,
saying what protection is lost and linking here.

Value forms: `<integer>` a whole number from 1, at most 15 digits; `<time>` a whole number from 1, at most 9
digits, with the unit `ms`, `s`, `m` or `h` (`10s`); `<buffers>` a count (1 to 4 digits) and a size of at least `1k`
separated by a space (`4 8k`; the size in bytes or with `k` or `m`, at most 7 digits); `<path>` an absolute file path
(letters, digits and `. _ / -`). "Weaker" lists the values that print the `SECURITY:` line: "above" compares numbers
by value, times by duration, and buffers by count or size.

| <a id="modsec_rule_engine"></a>`MODSEC_RULE_ENGINE` | `On` | ModSecurity's rule engine: On inspects requests and blocks attacks, DetectionOnly inspects and logs only, Off switches the WAF off. Attacks are no longer blocked: DetectionOnly only logs them, Off does not even inspect requests. | DetectionOnly for a first period on a new site, to find false positives in the audit log before blocking. |
| <a id="modsec_paranoia"></a>`MODSEC_PARANOIA` | `1` | OWASP CRS blocking paranoia level: how many and how strict the rules that block are. | <a id="modsec_anomaly_inbound"></a>`MODSEC_ANOMALY_INBOUND` | `5` | OWASP CRS inbound anomaly score threshold: a request is blocked when its matched rules add up to this score (one critical match scores 5).
